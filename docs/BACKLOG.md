## A. Document parsing: a `DocumentParser` seam and the OCR decision

Raised by a discussion about adding an OCR / document-AI model (PaddleOCR-VL, MinerU, Baidu Unlimited-OCR). Decision: no OCR in the pipeline; document the seam and the reasons.

- Introduce a `DocumentParser` type: a name and `parse(bytes)` → pages with text, line boxes and a character count. The pdf.js extractor is the only implementation, the same pattern as `TtsProvider`.
- Write down the contract for any parser: it returns page text and line positions (without positions the page frames can't work). Quotes are substrings of that text; for an OCR parser that is recognised text, not the document's own, and the UI should say so.
- Delivery notes paragraph:
  - why there is no OCR: out of scope per the brief ("no scanned-page OCR"); lower text fidelity than the text layer; a GPU service Vercel can't host; seconds per page instead of ~0.3 s; documents would leave the browser;
  - how PaddleOCR-VL or MinerU would plug in (the official MinerU repository is `opendatalab/MinerU`; a link in that discussion pointed to a fork);
  - a rough cost.
- Effort: ~30 min with the code, ~10 min for the paragraph alone.

## B. Tables

There is no test with a table, and a table is the one place where the text layer can lose structure.

- Risks:
  - rows become text lines ("A 20 20°C"), so an empty cell shifts the values after it;
  - the column detector (`pdf.ts`) may read a table with two text columns (Symptom | What to do) as two page columns, list all symptoms, then all fixes, and lose the pairing.
- Plan:
  - a one-page fixture generated by `scripts/make-fixtures.ts` with a spec table (Model / Max load / Temperature / Warranty, one empty cell) and a troubleshooting table (sentences in both columns);
  - tests in `eval/expected.json`, committed before their first run: a cell lookup, a comparison across rows, an empty cell → not_found, symptom → fix, one Russian question;
  - a unit test that every table row stays whole.
- If they fail, fix it on the text layer, not with OCR: detect blocks with aligned columns, keep rows whole, and attach the headers to each row as context.
- Effort: 30–40 min, plus 30–60 min if a fix is needed.
